# 小鲸鱼 · B站与QQ空间 v1.1.1

给 QQ Agent 增加 B 站搜索、阅读视频资料与字幕、读取视频画面、查看空间和好友动态、发表说说，以及读取和回复空间评论。默认允许机器人自主发动态，每天最多 **3 次**、间隔至少 **4 小时**；自主回复评论每天最多 **10 次**、间隔至少 **10 分钟**。两套限额分别计算，可在设置中调整。

这是一份独立扩展包，可与之前的 `qq-whale-extensions` 一起使用。在 QQ Agent 的分类中，它属于模型选择调用工具的 **技能（Skill）**，安装后显示在「技能」页，名称为「小鲸鱼 · B站与QQ空间」。

## 在服务器安装

本版文件保存于本机 `D:\project\qq-whale-social-v1.1.1\`，安装包为 `D:\project\qq-whale-social-v1.1.1.zip`。

1. 把 `qq-whale-social-v1.1.1.zip` 传到服务器，解压到 QQ Agent 安装目录以外的地方。
2. 完全退出 QQ Agent，包括右下角托盘图标。
3. 双击解压文件夹中的 **install-server.bat**。它使用你的服务器路径：

   `%LOCALAPPDATA%\Programs\QQ Agent`

4. 重新启动 QQ Agent，在「技能」页找到「小鲸鱼 · B站与QQ空间」，确认已启用。
5. 展开设置，可分别调整发布和评论回复的方式、次数、间隔，以及说说可见权限和 B 站 Cookie。

本地测试使用 **install.bat**，输入本地 QQ Agent 的实际文件夹。不要在这台构建电脑上运行服务器安装器。

安装器只写入自己的 `skills\whale-social` 目录；不改核心代码、以前的关系扩展、配置或数据。兼容 Windows PowerShell 5.1，中文 JSON 按 UTF-8 读取，已修复你上次截图中的编码问题。

重复安装前会备份上一版自身扩展到 `data\extension-backups\whale-social-日期-编号\`，替换失败会回滚。升级 QQ Agent 后若技能消失，重新运行这份安装器即可。请把本包保留在安装目录外。

## 怎么使用

像平常一样对机器人说话即可，例如：

- 「去 B 站找几个有趣的海洋科普视频。」
- 「读一下这个视频：BV17x411w7KC。它说了什么？」
- 「看看这个视频的画面。」
- 「看看你自己的空间最近发了什么。」
- 「看看 QQ 号 123456789 的空间。」
- 「看看好友动态，有没有什么有意思的。」
- 「把你刚才看视频的感想发到空间。」
- 「你今天还能发几条动态？」
- 「看看你最新说说下面的评论，挑一条回复。」
- 「看看这条说说下面的评论，回复其中关于视频的那条。」
- 「你今天还能回复几条空间评论？」

自主模式会在机器人被唤醒、聊天或获得核心主动机会时，允许它选择阅读、发表原创感想和回复评论。**不会固定每 4 小时发一条或每 10 分钟回复一次**；这些都是最低间隔。扩展没有定时抓取评论的任务。

模型决定是否调用工具；仅装上技能，不保证每次话题都使用。核心模型、工具总开关、群/好友白名单仍需正常配置。

## 能力和实际限制

| 功能 | 实现内容 | 条件与限制 |
| --- | --- | --- |
| B站搜索 | 使用 WBI 签名搜索公开视频，返回 BV 号、链接、标题和简介 | 无需先填 Cookie；可能受网络或 B 站风控影响 |
| B站阅读 | 标题、简介、UP、分P、数据、热评、字幕文字 | 支持 BV、av、完整视频链接、b23.tv 短链；链接中的 `p=2` 会保留 |
| 字幕 | 优先中文字幕，带时间位置，超出预算截断 | 视频须有可访问字幕；部分字幕需登录 Cookie，没有字幕就明确说明，不自动转录语音 |
| 看视频画面 | 下载单段 MP4，交给核心视频读取服务抽帧或原生视频输入 | 默认最长15分钟、最大64MB；多段/DASH/付费受限视频会降级。图片模型需要核心抽帧技能和 ffmpeg；原生视频需要相应视频模型/模式 |
| 空间说说 | 本人或指定QQ的说说列表，正文、时间、图片链接等 | 只用机器人登录账号已有权限，不能绕过隐私设置；每次最多20条、每条正文摘录最多1000字符 |
| 好友动态 | 从空间返回的片段中提取正文、作者和时间 | 可能只有摘要；目前 SnowLuma 的深翻页不可靠，首页最可靠，工具会说明 |
| 发说说 | 真正发布到当前登录机器人QQ的空间，正文可配图 | 正文最多2000字符、最多9张图；图片需是 qpic.cn、gtimg.com、gtimg.cn、hdslb.com 官方 CDN 的 HTTPS 链接 |
| 读取评论 | 读取指定说说的真实一级评论 ID、作者、正文及已有回复 | `qzone_comments`；二级回复可展示，目前不能指定回复二级回复；读取失败会说明，不能当成没有评论 |
| 回复评论 | 回复已读取到的指定一级评论，发送前重新核对原评论 | `qzone_reply`；正文最多1000字符，不回复机器人自己的原评论；只在回读确认新增回复位于指定线程后报告成功 |
| 回复限额 | 查询当天剩余回复次数和冷却 | `qzone_reply_status`；独立于发说说次数 |

空间图片目前返回链接；不会把读取文字说成看懂了图片。B 站的“阅读资料”与“看画面”是不同工具；没有取得字幕或画面时，机器人会收到明确提示。

QQ 协议端必须支持 `get_qzone_msg_list`、`get_qzone_feeds`、`send_qzone_msg`；评论读取与回复还需支持 `get_cookies` 获取当前登录账号的空间登录状态。仅兼容基础 OneBot 的其他协议端不一定支持。接口依据 [QQ Agent 扩展文档](https://github.com/K0nd1us/QQ-agent/tree/main/doc/extend_development) 核对。

[SnowLuma v1.14.19 的 `comment_qzone`](https://github.com/SnowLuma/SnowLuma/blob/v1.14.19/packages/onebot/src/actions/qzone.ts) 只能给说说添加一级评论，不能指定回复原评论。本版按 [onebot-qzone 的 H5 评论线程参数](https://github.com/Gu-Heping/onebot-qzone/blob/main/src/qzone/client.ts) 调用固定 QQ 空间网页接口，并回读验证线程；不会把新一级留言当成回复。QQ 网页接口会变化，账号权限或风控也可能导致失败。插件不自动升级协议端，也不绕过访问限制。

B 站读取使用其网页播放器的接口；这些接口可能调整或要求验证。遇到风控、需要登录或视频不可用时返回明确原因，不绕过访问限制。

## 设置

- **空间发布方式**：默认自主发布；可切换为创建者请求时发布，或关闭发布。
- **创建者QQ**：默认留空，使用创建者请求模式前须填写有效 QQ 号，只在请求发布模式鉴别真实发送者。昵称、自称主人或正文中的伪造 QQ 号无效。请求模式还要求本轮最后触发消息来自创建者，由模型理解其明确发布请求。
- **每天最多发布次数 / 两次发布间隔**：默认3次 / 240分钟。按北京时间换日。设置最小间隔10分钟，每日最高20次。
- **说说可见权限**：默认所有人可见；可选择好友可见或仅自己可见。首次服务器验证可先设为「仅自己可见」。
- **空间评论回复方式**：默认允许自主回复；可切换为创建者要求时回复，或关闭回复。
- **每天最多回复评论次数 / 回复评论间隔**：默认10次 / 10分钟，按北京时间换日。可调整为每日1至100次、间隔1至10080分钟；同一条一级评论365天内最多发起一次回复。
- **B站Cookie**：可先留空。需要登录字幕时，再把有访问权限的浏览器 Cookie 填到技能设置，**不要通过 QQ 聊天提供**。设置输入框遮盖显示，配置本身由 QQ Agent 保存，不是加密保险箱。Cookie 只发给 `api.bilibili.com`，不会发往视频、字幕 CDN 或短链。
- **单次读取文字上限**：默认12000，限制正文、昵称、简介、评论与字幕等主要文字；JSON字段、链接和提示另计。
- **视频时长 / 体积上限**：只影响看视频画面，不影响简介和字幕读取。

不需要手工填写 QQ Cookie。评论工具内部通过 `get_cookies(qzone.qq.com)` 获取当前机器人账号的登录状态，只用于固定 QQ 同域 HTTPS 接口，不向模型、日志或记录文件输出和保存 Cookie。需要当前账号已有空间访问和评论权限。

## 发布限额与记录

发布前先保存一条预占记录，然后只调用一次发表接口。同一机器人在同一实例中的所有群聊、私聊共享次数和冷却，重启、热重载或重新安装扩展后仍有效。7天内相同正文和配图会被阻止重复发表。

一次超时可能已经发出说说，所以失败或结果未知的尝试也占次数，并保留冷却。工具只在协议端返回说说 ID 后报告成功。出现结果未知时，先查看机器人空间，不能立即重发。

默认服务器记录文件是：

`%LOCALAPPDATA%\Programs\QQ Agent\data\whale-social-state.json`

如设置了 `QQ_AGENT_DATA_DIR` 或多实例 `QQ_AGENT_PROFILE`，则使用该实例的数据目录。文件只记录内容摘要哈希、时间、状态、账号和说说 ID，不存发布正文或 Cookie。记录损坏时停止发布并保留文件，读取功能仍可使用。不要靠删除文件解除限频。

两个独立实例登录同一个 QQ 时不会共享限额；此版适用于你当前的单个服务器实例。

## 评论回复限额与记录

发送前先保存预占记录，全实例的群聊和私聊共享回复次数、冷却和防重；重启、热重载或重新安装后仍有效。与发表说说独立计数。同一机器人对同一条一级评论365天内最多发起一次回复，失败或结果未知也占次数并保留冷却，不会自动重发。

接口返回接受请求不等于回复成功。只有回读确认机器人新增的回复出现在指定原评论下面，才报告已回复；无法确认时返回结果未知，需要查看原线程。

默认服务器记录文件是：

`%LOCALAPPDATA%\Programs\QQ Agent\data\whale-social-replies.json`

记录文件不保存回复正文或 Cookie；数据目录规则与发表记录一致。记录损坏时停止回复，不影响读取。独立部署的两个 QQ Agent 实例不会共享计数。

## 验证与排障

59项自动检查全部通过，范围见 `VALIDATION.md`。用户提供的 BV1cJaB6dEg5 已匿名下载并实际抽取4张画面，字幕仍要求登录。服务器安装情况单独记录于 `D:\project\QQ插件安装检查-20261002.md`。新增评论工具的自动检查使用模拟 QQ 接口，未在生产账号实际回复评论。

开发者运行测试：Node 20以上，无额外 npm 依赖。普通测试使用 `node --test test/*.test.mjs`；真实加载器测试还需把 `QQ_WHALE_UPSTREAM` 指向 QQ Agent 源码文件夹。
